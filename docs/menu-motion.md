# Menu motion

All `Windows11ContextMenuStrip` surfaces share the same opacity transitions:
160 ms opening and 100 ms root closing, using cubic ease-out and elapsed time rather
than a fixed opacity increment. The main tray/widget menu, nested folders and
shortcut context menus use this class. The existing 200 ms folder hover delay
is unchanged.

Menu items inherit their owning menu's font. Autogenerated submenus inherit the
effective font from their owner item, including DPI changes, rather than keeping
a separately constructed copy of the saved point size. This keeps all nested
levels consistent with the main menu without changing the saved font or row height.

Opening animates the actual menu using native alpha attributes with a stable
layered window style. It does not toggle WinForms' layered style at full opacity.
Closing preserves the normal WinForms close lifecycle immediately. A temporary
image finishes the visual fade without keeping the menu, keyboard focus,
outside-click hook or input capture alive. The image uses a layered tool window
with no activation and transparent hit testing; it has no taskbar entry. New
menus cancel old images, and disposing a menu also disposes its fade image.
Only root dismissal creates an image, after the close callback has returned;
sibling submenu navigation never opens a temporary Form. A root ignores a
passive AppFocusChange close when its foreground window has not changed or is
still a visible menu. Explicit click, keyboard and programmatic close requests
continue to dismiss it. Settings explicitly closes the menu, cancels fade images
and queues the dialog until WinForms has finished closing the popup.
Images stay in memory and are released at the end of the effect.

Windows menu/client-area animation preferences and high contrast disable the
effects. The application reads these settings without changing them. A failed
or oversized closing-image allocation falls back to immediate dismissal.

Verification commands:

```powershell
dotnet run --project tests/CoreSmoke/CoreSmoke.csproj -c Release -- menu-motion
dotnet run --project tests/UiSmoke/UiSmoke.csproj -c Release -- menu-typography
dotnet run --project tests/CoreSmoke/CoreSmoke.csproj -c Release -- all
dotnet run --project tests/WidgetPrototypeSmoke/WidgetPrototypeSmoke.csproj -c Release -- --render bin/Release/net8.0-windows/TaskFolder.dll
dotnet run --project tests/UiSmoke/UiSmoke.csproj -c Release -- menu-lifetime-widget-auto
```

The motion lane checks timing, Windows preference mapping, accepted/cancelled
close callbacks, reusable opacity, hidden snapshot styles/hit tests, ownership
and resource cleanup. It opens no visible menu. Native visual acceptance remains:
root/submenu opening and dismissal, rapid reopen, outside click into another app,
shortcut launch, Escape/Alt+Shift and search focus, light/dark themes and mixed DPI.
The native lifecycle fixture drives its own WinForms menu/dialog callbacks,
including a transparent widget owner, without injecting OS pointer input. It
checks submenu switching, unchanged-foreground notifications, explicit close
reasons and visible Settings dialogs that are cancelled without saving.
The stable local `1.3.0` package includes these changes; installation evidence is
recorded separately from visible animation acceptance.

The hidden typography fixture covers configured 9/12/18 pt fonts, DPI callbacks
144/192/96/192, two nested levels and submenus created after a DPI change. It
checks effective font equality, text measurements and row heights without showing
menus or changing display settings. Physical mixed-DPI visual testing is separate.

Native contracts were checked against the
[WinForms dropdown implementation](https://github.com/dotnet/winforms/blob/v8.0.11/src/System.Windows.Forms/src/System/Windows/Forms/ToolStripDropDown.cs),
[layered-window hit testing](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features),
and [SystemParametersInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow).
